# League Manager Pilot Acceptance Checklist

## Setup

- [ ] League workspace created under the correct league name
- [ ] Pilot season dates confirmed
- [ ] Real division imported
- [ ] Parent clubs and teams reconciled
- [ ] Every active team has a home venue
- [ ] Shared physical grounds use the same ground-share key
- [ ] Simultaneous fixture limits confirmed for every venue/group
- [ ] Available, reserved and closed playing dates entered
- [ ] League, division, club, team and venue blackouts entered

## Generation

- [ ] Correct single or home-and-away frequency selected
- [ ] Required fixture count matches the league’s expectation
- [ ] Odd-team bye rounds handled correctly where applicable
- [ ] Home and away totals are balanced
- [ ] Existing locked fixtures retain their date, time and venue
- [ ] No team receives two fixtures on the same date
- [ ] Ground-share capacity is respected
- [ ] Unresolved fixtures include a usable reason

## Operator workflow

- [ ] Fixture secretary can filter by division, team, venue and status
- [ ] Manual date, kick-off and venue changes save correctly
- [ ] Fixtures can be locked and retained in a new generation
- [ ] Unresolved-only regeneration preserves placed fixtures
- [ ] Two saved versions can be compared
- [ ] An older version can be restored as a new draft
- [ ] Draft versions can be deleted; published versions cannot

## Validation and publication

- [ ] Browser validation identifies all known test conflicts
- [ ] Server validation independently reaches the same blocking outcome
- [ ] Publication is rejected while blocking issues remain
- [ ] A valid draft publishes successfully
- [ ] The previous published version is archived
- [ ] The official fixture registry reflects the published version
- [ ] Audit history records generation, edits, restoration and publication
- [ ] CSV export contains division, round, date, time, teams, venue and status

## Pilot outcome

- [ ] League confirms the export is usable in its current process
- [ ] Time saved against the current scheduling method is recorded
- [ ] Missing mandatory rules are documented
- [ ] Requested preferences are separated from hard constraints
- [ ] Postponement/rearrangement workflow is agreed for the next phase
- [ ] Pilot sponsor agrees whether to continue to operational trial
