# Disclosure and data-room plan

## Stage 1 — initial approach

Suitable for email and first call:

- non-confidential teaser;
- synthetic demo URL;
- high-level module list;
- founder background and pilot context;
- request for strategic discussion.

Do not disclose:

- source code;
- database schema detail;
- live credentials;
- detailed algorithms;
- private valuation minimum;
- employment contract;
- complete ChatGPT export;
- live HSM personal data.

## Stage 2 — mutual NDA and confirmed interest

Provide a controlled data room containing:

1. corporate/founder and IP ownership pack;
2. architecture summary;
3. module and roadmap inventory;
4. repository statistics and quality-gate evidence;
5. security overview and dependency inventory;
6. redacted pilot evidence;
7. product demonstration recordings or scripts;
8. known-defect and technical-debt register;
9. proposed integration workshop agenda;
10. draft IP asset schedule.

## Stage 3 — technical diligence

Provide read-only, time-limited access to a clean diligence repository or encrypted source archive containing only committed files. Exclude `.env`, `node_modules`, local backups, production data and personal records.

Required controls:

- named authorised reviewers;
- access logging;
- no redistribution;
- no production deployment;
- clear open-source licence inventory;
- checksum recorded at delivery;
- repository access revoked at the agreed point.

## Stage 4 — heads of terms and confirmatory diligence

Provide legal, tax and transaction materials through advisers:

- final ownership analysis;
- employment/IP contract review;
- tax structure advice;
- warranties and disclosure letter;
- final asset schedule;
- transition plan;
- technical acceptance tests;
- consideration and earn-out definitions.
